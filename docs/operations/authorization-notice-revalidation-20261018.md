# T02：迟到的权限通知误关新连接

组合修复的隔离 HTTP 验证 run 39112990274 出现 40 通过、1 失败。
失败是游客获批为学生后，刷新会话并重新建立 WebSocket，仍收到 4403 权限变更关闭。

根因：`authorization.changed` 来自 Outbox，可能晚于新连接建立才由 Worker 发布；
Web 订阅器按 user_id 无条件关闭所有连接，没有核对连接持有的权限版本。
所以旧通知或重复通知会把已经拿到新权限的连接一起关闭。

修复仅改变通知消费：按连接重新检查数据库会话和当前 Principal，旧权限或已撤销会话仍立即关闭；
新权限连接保留。数据库校验失败时也会断开，返回可重试的 1013，且不终止通知监听器。
每个连接的检查有 5 秒上限，不修改 idle/绝对有效期，也不刷新 last_seen。
管理员直接关闭用户连接的操作仍保留原来的全部关闭行为。

验证包含新旧连接共存、重复通知、其他用户不受影响、会话撤销、校验失败和取消。
真实 HTTP 用例额外在重新连接后主动重发三次通知，确认仍能 ping/pong，HTTP 会话仍有效。

这确认了一种可复现的断线原因，不能据此认定所有历史公测掉线都来自此处。
尚需 CI、测试站部署和现场验收；本次未部署或修改任何线上用户/权限数据。
