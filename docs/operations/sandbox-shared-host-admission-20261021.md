# 共享主机代码执行保护与当前容量边界

## 用户约束与已取得的证据

- 目前只能使用现有 2 核 / 8GB 服务器，测试站与正式站共用。
- 保留现有交互式内核及变量；用户明确不采用每次执行后销毁环境的单次运行模式。
- TEST 已应用每沙箱 512 MiB / 1 CPU、池上限 4、TEST Manager 整机计数保护 6、代码执行并发 2、动态预热 1～2、主机预留 3072 MiB / 15 GiB；AI Worker 为 2×4。
- aeb8fa6 现场 2 用户及 3 用户混合代码与变量保留通过，自己的环境回收及动态补池通过；84 次普通会话检查全部成功，最慢 213.84 ms。
- 3 用户保留期自有内核合计采样最高 609.18 MiB，主机最低可用约 3340.66 MiB，CPU 短时 100%。创建新 512 MiB 沙箱需 3584 MiB 可用内存，最低创建余量约 -243.34 MiB。
- 后续当前配置的 4 用户满池检查通过：4 个独立内核保留变量，合计采样最高 823.23 MiB；44 次普通会话检查全部成功，最慢 255.31 ms；每用户混合代码及变量复核约 8.55～9.17 秒。回收和补池通过，核心容器与环境变量未变；整轮最低可用 3095.66 MiB，仅比 3 GiB 测试保护线高约 23.66 MiB，CPU 短时 100%。

上述证据已验证到 4 个独立内核的小规模使用，尚不支持 41/120 个独立代码环境同时保留或执行。仅提高数量上限不会增加 CPU 或内存，也不能通过自动重置其他用户变量腾位置。

## 本批源码修复

1. 模型 `run_scratch` 原来直接调用 Docker，未使用交互执行信号量或主机内存、磁盘和数量保护。现在先取得有等待期限的共享主机锁和代码执行名额，重新核对池数量与主机资源，才启动一次性实验。
2. Scratch 不占用户交互式运行时表中的行。其完整生命周期保留共享主机锁，reconcile 的 Docker/数据库清单比对和孤儿回收使用同一把锁，防止把仍在执行的实验误删；进程失败后遗留容器仍可在后续 reconcile 中正常回收。
3. 共享 flock 改为非阻塞轮询，取消等待不会留下后台阻塞线程在稍后误拿锁。锁和执行名额在失败、取消、超时后释放。
4. Scratch 取消或超时后终止并回收自己的 Docker CLI，并针对 Manager 生成的精确名字清理容器；交互内核超时的 CLI 回收也有时间边界。
5. 交互执行的鉴权和 nonce 消耗移到取得执行名额后。排队期间退出登录、修改授权或重建内核，不能靠排队前的旧检查继续执行。

### 对使用方式的影响

- 保留交互式变量、现有界面和用户隔离方式；不自动重置或退出别人的环境。
- 资源满时模型实验返回可重试的容量错误；不会绕过数量或内存保护继续新建。
- 为便于现有主机安全运行，scratch 全生命周期暂占共享主机创建锁，跨环境 scratch/创建可能串行；普通已分配交互执行仍使用配置的代码并发。
- 该锁仅协调遵循锁约定的进程。正式站旧版本仍须在其单独发布时更新，TEST 合并不能证明正式站的所有代码路径已经获得新保护。

## 验证与发布

- 本地回归覆盖混合 scratch/交互并发、池满/主机保护拒绝启动、排队超时、排队期间注销、取消后精确清理，以及取消 flock 等待后的可再次获取。
- 本地相关回归 89 通过、12 个真实 Docker/条件集成用例跳过；Ruff 和 diff 检查通过。真实 Docker 检查仍待该提交的 CI，不能把跳过写成通过。
- Linux CI 新增真实 MySQL + runsc 验证：真实 scratch 运行期间 reconcile 等待其锁；任务成功且 --rm 回收后再做孤儿比对；模拟资源不足时不得启动新容器。
- 本地没有 Docker，真实 runsc 结果以 CI 为准。合并前需完整 CI 与既有 HTTP/Manager 生命周期通过。
- 本批针对 develop/TEST；生产发布、Worker 调整、额度/账号改动不在本批中。所有相关问题集中为一个 PR；后续修正继续追加原 PR。
