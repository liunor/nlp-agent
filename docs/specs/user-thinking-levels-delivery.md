# 用户思考程度与额度计费

## 行为

- 聊天输入框提供「快速、轻度、深度、极致」四档，用户偏好按已认证账号保存。切换账号、退出登录及过期请求不会覆盖当前账号状态。
- DeepSeek 和 GLM 的请求按当前模型能力映射到相应思考参数；不支持此能力的模型保留原有发送流程。
- 每个已接纳的回合按所选档位冻结计费：快速 1、轻度 2、深度 4、极致 8 额度。界面不显示消耗。取消、失败、重试和 Worker 恢复沿用同一回合的冻结快照和幂等结算规则。
- 扣费使用现有 Credits 策略、额度桶和账本；现有 Token 额度的预留、日志和调用保护机制继续独立工作。不会自动发放新余额；账号需要由现有额度管理分配有效策略和额度。
- 开发者模型编辑器只管理模型、生成参数、重试等非思考字段。旧版思考字段在 API 中被拒绝；历史覆盖中的思考字段不再参与运行时配置。

## 接入与验证

- 用户管理页面可查看指定用户额度并跳转额度管理，所有额度管理 API 仍要求系统范围权限。用户偏好 API 只从已认证会话确定用户身份。
- 本地回归覆盖账号隔离、预设校验、请求冻结、Turn 生命周期及额度结算。完整 CI 还需要可用的 MySQL 服务；本地使用无服务的测试 DSN 时，真实数据库集成用例无法完成。
- 按产品决定，本次未执行 GLM 真实付费调用。上线前应在具备正式额度策略、Provider 密钥和测试账号的环境做端到端验收。
