# 学习主题、教学会话与教师目录规格

## Problem Statement

学生端目前的主题、难度与教学方式没有完整、可靠地贯通教师配置、后端协调器和普通聊天。主题会与真实问题发生不必要的冲突；引导、练习和复习缺少独立且可恢复的结构化教学状态。教师空间中课程与目标、Prompt 模板没有有效用途，多个页面内容重复，主题、知识点、出题蓝图和复习蓝图也没有可用的完整 CRUD 与生命周期控制。

教师需要能维护同一份主题、知识点和蓝图，学生端与后端需要即时使用它们；普通聊天 Session 和历史 Turn 必须保持不受影响。系统还需要可评估的练习证据，供复习和教师学习分析使用。

## Solution

建立教师拥有、学生与 Coordinator 共同消费的教学目录：Topic、Knowledge Point、Exercise Blueprint 和 Review Blueprint。Topic 和 Knowledge Point 均有稳定 ID、可编辑内容与启用/停用状态；知识点正文使用 Markdown，并形成当前主题的教学范围。

学生的学习选择为可选 Topic、默认 `beginner` 难度和默认 `explain` 模式。未选择 Topic 时不向模型注入主题范围，真实问题按普通聊天处理；选择 Topic 后，用户当前问题优先于主题范围，难度和教学方式始终生效。系统不额外使用模型识别或自动切换 Topic。

引导、练习与复习各自使用独立的结构化教学会话，与普通 chat Session 关联但绝不替换或改写聊天记录。出题和复习由服务器在当前 Topic 的可用蓝图中随机分配一个，保存不可变快照，并将评分证据写入可分析的数据结构。

## User Stories

1. 作为学生，我希望默认以入门难度和讲解模式开始对话，以便无需预先配置就能提问。
2. 作为学生，我希望可以不选择主题，以便普通问题不会被课程范围约束。
3. 作为学生，我希望选择启用的主题，以便得到与当前课程相关的背景和知识点约束。
4. 作为学生，我希望我的本次问题优先于当前主题，以便问到相邻主题时仍能得到直接答案。
5. 作为学生，我希望难度和教学模式在任何主题状态下持续生效，以便回答风格符合我的学习需要。
6. 作为学生，我希望手动切换主题，而不是被模型自动猜测和改变学习路径，以便课程状态可预测。
7. 作为学生，我希望在讲解模式获得结论、原理、例子和小结，而不产生额外教学会话。
8. 作为学生，我希望引导模式能记住本次学习目标、已掌握内容和误解，以便问题能逐步推进。
9. 作为学生，我希望第一次在引导模式发送的消息成为学习目标，以便不需要重复说明目标。
10. 作为学生，我希望练习模式自动获得适合当前主题的题目，以便无需选择或理解教师蓝图。
11. 作为学生，我希望复习模式结合知识回顾和题目练习，以便巩固已学知识。
12. 作为学生，我希望在主题未配置可用练习或复习蓝图时看到明确配置提示，以便知道问题不在于我的操作。
13. 作为学生，我希望题目支持选择、填空、表格、公式、代码和坐标图，以便练习形式符合知识内容。
14. 作为学生，我希望题目、答案与讲评能安全呈现表格、公式、代码和 Mermaid 图，以便阅读复杂题面。
15. 作为学生，我希望教学会话在切换主题或模式、主动完成或长期无操作后停止，而普通聊天仍可继续。
16. 作为学生，我希望每次新的练习都独立保存，以便后续复盘我的多次尝试。
17. 作为学生，我希望得到按评分点计算的分数和简短讲评，以便知道具体薄弱处。
18. 作为教师，我希望创建、编辑、启用、停用和恢复 Topic，以便维护课程范围且保留历史。
19. 作为教师，我希望新建或修改 Topic 后立即在教师页和学生选择器中可见，以便验证配置已生效。
20. 作为教师，我希望为 Topic 创建、编辑、排序、启用和停用 Markdown 知识点，以便精确约束教学范围。
21. 作为教师，我希望停用 Topic 或知识点而不是删除它，以便不破坏历史学习记录和分析。
22. 作为教师，我希望创建出题蓝图和复习蓝图，以便分别定义练习与复习策略。
23. 作为教师，我希望蓝图可在草稿、启用和停用之间切换，以便只让准备好的内容参与新会话。
24. 作为教师，我希望蓝图同时包含结构化题型、数量、难度、知识点、分值和评分点，以及可编辑 Markdown 指令，以便兼顾统计和灵活题面。
25. 作为教师，我希望修改或停用蓝图不影响已经开始的练习，以便历史评分结果可追溯。
26. 作为教师，我希望学生不能查看或选择蓝图，以便教学策略由课程配置统一控制。
27. 作为教师，我希望在教师首页看到配置与学习风险概览，以便快速了解课程运行状态。
28. 作为教师，我希望在学生问题页看到学生提问的统计概览与主题/难度/模式分布，而不显示学生逐条问题原文，以便在保护隐私的前提下了解困惑来源。
29. 作为教师，我希望在学习分析页看到按知识点、评分点和成绩汇总的学习证据，以便发现薄弱项。
30. 作为系统维护者，我希望教师目录、教学会话和普通聊天数据彼此隔离，以便新增教学能力不干扰既有 Session 和 Turn。
31. 作为系统维护者，我希望旧主题名称只在唯一匹配时迁移为 Topic ID，以便不猜测或错误改写历史记录。
32. 作为系统维护者，我希望动态提示词按版本化 Markdown 模板组合，以便教师目录和模式策略可维护地影响 Coordinator。

## Implementation Decisions

- Topic 使用不可变 `topic_id` 作为身份，名称可编辑。Topic 状态为 enabled 或 disabled；disabled Topic 不能在学生端新选取，也不能开始新教学会话，但历史关系和显示名称快照保留，可重新启用。
- Knowledge Point 使用不可变 ID、标题、排序、状态和可编辑 Markdown 正文。仅当前 Topic 下启用的知识点会进入新提示词、蓝图候选范围和新教学会话。
- 后端为当前 Topic 组装全部启用知识点的有序、长度受限 Markdown。超过预算必须报告教师配置问题，不能静默截断或额外进行语义检索。
- 学生选择的默认值为 Topic 未选择、level 为 beginner、mode 为 explain。未选择 Topic 时主题和知识点提示词为空。
- 优先级为：安全和事实准确、用户当前明确问题、用户显式主题切换、当前 Topic 范围、默认讲解。level 和 mode 始终生效。系统不因问题内容使用额外模型调用自动识别或切换 Topic。
- Coordinator 在既有全局缓存提示词上动态拼接版本化 Markdown：Topic/Knowledge Point、三个 level 模板、四个 mode 模板，以及活跃教学会话和蓝图快照片段。
- explain 不创建教学会话；socratic 在第一条学生消息时创建或恢复同一 chat Session 和 Topic 的唯一活跃 Guided Session；practice 与 review 在第一条学生消息时各自创建新的 Exercise Session。
- Guided Session 保存目标、当前阶段、已掌握概念、误解、上次问题和时间戳。目标来自引导模式的首条学生消息，仅在学生明确切换目标或 Topic 时变更。
- Exercise Session 保存模式、Topic、服务器分配的蓝图快照、题目、作答、尝试次数、评分、讲评和生命周期。它可包含连续多题；每次新练习会创建新的 Session。
- 活跃教学会话在明确完成、Topic 变更、mode 变更或 30 分钟没有学生消息后变为完成、取消或过期历史，且不再注入 Prompt。普通 chat Session 不因此关闭。
- Blueprint 属于一个 Topic，按练习或复习分类，具有 draft、enabled、disabled 状态，并含关联知识点、题目数量与类型、难度、分数、加权评分点和 Markdown 指令。仅 enabled Blueprint 可分配。
- 服务器从当前 Topic 下满足条件的 enabled Blueprint 中均匀随机分配一个；学生端既不显示也不选择 Blueprint。若无候选项，不创建教学会话并返回“该主题尚未配置练习/复习蓝图。”。
- 创建 Exercise Session 时保存完整 Blueprint Snapshot；后续编辑、停用或恢复教师原始 Blueprint 不影响已存在会话和证据。
- 题目和讲评使用受控 Markdown：文本、列表、表格、代码、公式和 Mermaid 图。拒绝原始 HTML、脚本和任意外部嵌入。可评分选择、填空和评分点同时以结构化数据存储。
- 批改结果必须包含评分点命中、逐点得分、0–100 标准化总分、通过状态和简短反馈。后端验证其与 Blueprint Snapshot 一致后再保存；自然语言讲评不得覆盖分数。
- Learning Evidence 保存题目、答案、尝试、评分点、成绩、关联知识点、完成时间和必要快照，不保存模型推理过程。它是教师分析和复习决策的数据源。
- 教师空间拆为不同页面：首页概览、Topic 与知识点、出题蓝图、复习蓝图、学生问题、学习分析。移除无效的“课程与目标”和“Prompt 模板”页面及接口。
- 所有目录 CRUD 通过 FastAPI 真实连接持久化存储；创建、编辑、启停成功后刷新或可靠更新本地目录，使新增项立即出现在教师列表和学生选择器。
- 教师目录、Guided Session、Exercise Session 和 Learning Evidence 使用独立持久化结构，只通过 workspace、user、chat Session 和 Topic ID 关联，不改写既有普通 Session/Turn。
- 旧的主题名称在首次读取时仅可唯一映射时转换为 Topic ID；无法匹配或存在歧义时标为未分类。历史 Turn 不做批量重写，新 Turn 保存 Topic ID 与名称快照。
- 保持现有 `uv.lock` 原样，不修改、覆盖或提交其用户已有改动。

## Testing Decisions

- 测试只验证可观察行为、持久化结果和边界返回，不断言组件私有 state、Prompt 拼接实现细节或固定中文提示全文。
- 后端优先使用现有 HTTP API 与 WebSocket/Gateway 边界：验证目录 CRUD、workspace 隔离、状态过滤、Topic 未选择、动态学习上下文、模式会话创建/恢复/终止、蓝图随机候选约束、无蓝图提示、快照不可变性、评分结果校验和旧主题迁移。
- 前端使用组件/逻辑测试验证教师 CRUD 表单和启停操作的 API 交互、创建后列表可见、学生 Topic 下拉状态、默认 level/mode、以及聊天请求载荷。避免对样式、DOM 层级和内部 Hook 实现的脆弱断言。
- 在现有测试布局中扩展后端 `tests/` 和前端 `webui/src/**/*.test.ts(x)`，复用现有 WebSocket 客户端与 API 测试模式。
- 先运行与修改直接相关的测试，然后运行完整后端测试、前端测试、lint、WebUI build 和 Monitor build。失败必须定位和修复；只有能证明与本次改动完全无关的失败才可保留，并记录完整命令和证据。

## Out of Scope

- 根据自然语言内容自动分类、自动切换 Topic，或为此增加额外模型调用。
- 将历史普通聊天记录批量重写为新 Topic ID 格式。
- 物理删除 Topic、Knowledge Point 或 Blueprint。
- 允许模型输出并执行原始 HTML、脚本或任意外链内容。
- 保存或展示模型链式推理。
- 复杂图片题的生成、上传和视觉判卷；当前以受控 Markdown、公式、表格和 Mermaid 覆盖文本型题目与坐标图。
- 改动、覆盖或提交已有的 `uv.lock` 改动。

## Further Notes

- 术语以项目 `CONTEXT.md` 为准，并遵循 Blueprint Snapshot、Blueprint Assignment 与 Topic Lifecycle 的既有 ADR。
- Topic、Knowledge Point 与 Blueprint 的教师配置即时影响未来教学会话；活动或历史会话始终以创建时的结构化状态和快照为准。
- “主题尚未配置练习/复习蓝图”是后端的明确配置性响应，不得通过假装创建练习或回退到未知蓝图掩盖。
