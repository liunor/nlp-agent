# 用户管理系统改造 — 功能总结

## 一、注册与登录流程修复

### 1.1 注册流程完善

之前用户注册时存在多个问题，已全部修复：

- **用户名格式问题**：自动生成的用户名包含下划线，不符合验证规则。现在改为纯字母数字格式（如 user81356881xxxx），确保通过校验。

- **数据库写入失败**：注册返回成功但数据库中没有数据。根本原因是事务没有提交，`async with` 代码块退出时自动回滚了未提交的事务。现在在注册流程末尾正确调用了提交操作，确保数据真正写入数据库。

- **外键约束错误**：创建用户时需要同时创建工作区和成员关系，但 MySQL 外键要求父记录先存在。现在分两步处理：先创建用户和工作区，再添加成员关系。

- **验证码有效期调整**：短信验证码和图片验证码的有效期都从 300 秒缩短为 120 秒（2 分钟），提升安全性。

### 1.2 登录支持手机号

之前登录只能用用户名，现在支持用手机号或用户名登录，更符合用户使用习惯。

### 1.3 注册默认角色调整

新用户注册时默认分配"学生"角色（之前是"访客"角色），确保注册后能正常使用学习功能，不会出现权限不足的问题。

## 二、角色权限体系

### 2.1 四角色隔离

系统实现了四个角色的权限隔离，通过 RBAC（基于角色的访问控制）机制管理：

| 角色 | 说明 | 主要权限 |
|------|------|----------|
| **访客** | 仅浏览公开内容 | 查看个人资料、公开内容 |
| **学生** | 注册默认角色 | 创建学习会话、提交练习、查看学习进度 |
| **教师** | 教学管理人员 | 管理学习内容、创建班级、查看班级分析报告 |
| **开发者** | 系统管理人员 | 全部权限，包括系统配置和用户管理 |

### 2.2 角色升级 API

新增了角色分配接口，管理员可以通过 API 给用户分配或更换角色。例如将学生升级为教师，或分配开发者权限。

## 三、退出登录修复

### 3.1 问题描述

之前点击"退出登录"按钮后，虽然后端清除了会话，但页面没有跳转到登录页，用户仍然停留在当前页面，看起来按钮没有反应。

### 3.2 修复方案

现在退出登录后会：
1. 调用后端接口清除会话和 Cookie
2. 清空前端所有状态数据
3. **自动跳转到登录页面**

修复涉及学生工作台和管理后台两个位置的退出登录功能。
