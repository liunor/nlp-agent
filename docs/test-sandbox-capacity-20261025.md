# 测试站沙箱参数记录

2026 年 10 月 25 日，在现有 2 核、约 8 GB 且共用正式站的服务器上完成一次有限对照。应用版本为 `5bd89221f8c3c0ad29c33a3998c50653cf81ba50`。

| 项目 | 采用值 |
| --- | --- |
| 单沙箱内存限制 | 512 MiB |
| 单沙箱 CPU 限制 | 1 CPU |
| 测试站沙箱总数上限 | 4 |
| 整机受管沙箱数上限 | 6，包含其他环境 |
| 同时执行代码数 | 2 |
| 动态预热 | 开启，目标 1，最少 1，最多 2 |
| 主机可用内存预留 | 2560 MiB |
| 磁盘预留 | 15 GiB |

调整前，主机预留为 3072 MiB；创建下一个 512 MiB 沙箱需要至少 3584 MiB 可用内存。实际第 3 人领取时，可用内存约 3452 MiB，因此数量尚未达到上限，补池就被资源保护阻止了。提高数量上限无法解决这个条件。

本轮只把测试站沙箱管理器的预留降到 2560 MiB。4 个独立用户领取环境用时约 5.1～9.9 秒；4 人均完成混合代码和变量保留检查，共 8 次执行。测试内核合计内存峰值约 824 MiB，主机可用内存最低约 2846 MiB，CPU 瞬时最高 100%。普通会话观察 31 次均成功，最慢约 141 毫秒。自己的会话清理和动态补池均已确认，代码负载期间核心服务元数据保持一致。

这只验证了 4 人的小型混合负载。4 个保留内核与 2 路执行是不同限制；超过 4 人持续保留独立内核仍会等待。没有验证全班代码并发、每个沙箱打满内存、长时间计算，或真实对话与代码叠加。
